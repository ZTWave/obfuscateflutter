# Dart 源码注释清理设计

## 目标

为 `obfuscateflutter` 新增 Dart 源码注释清理功能。功能递归处理目标 Flutter
项目 `lib` 目录下的所有 `.dart` 文件，删除全部普通注释和文档注释，同时避免
破坏 Dart 字符串内容或改变非注释代码的 token 边界。

## 范围

- 仅扫描目标项目的 `lib/**/*.dart`。
- 包含普通业务源码和 `.g.dart`、`.freezed.dart`、`.gr.dart` 等生成文件。
- 删除行注释 `//`、文档行注释 `///`、块注释 `/* */` 和文档块注释
  `/** */`。
- `// ignore`、`// ignore_for_file` 等基于注释的 Analyzer 指令也会删除。
- 不处理 `lib` 目录以外的 Dart 文件。
- 不提供注释恢复或备份功能；现有工具的修改前提交或临时目录执行建议继续适用。

## 实现方案

新增 `lib/dart_comment_cleaner.dart`，使用 `package:analyzer` 的词法扫描结果定位
注释 token。该方案能够区分真正的注释和字符串、raw string、三引号文本中的
`//`、`/* */` 字符。

对每个文件收集注释的源码区间，再从文件末尾向前执行替换，避免前一次改写使后续
offset 失效。删除注释时遵循以下边界规则：

- 注释包含换行时，清理阶段先保留原有换行字符，避免 token 粘连；后续
  `dart format` 可以规范化换行和空白。
- 单行块注释位于两个可能粘连的 token 之间时，以一个空格替代。
- 其他注释替换为空字符串。
- 文件没有注释时不写回，避免无意义地更新修改时间。

清理后再次使用 Analyzer 解析修改后的源码。若结果新增语法错误，则不写回该文件，
并将文件记录为失败。源文件原本已有的语法错误不作为清理失败依据；只有清理后新增
的错误才阻止写回。

文件成功写入去注释源码后，先收集其路径；全部注释清理结束后，使用当前 Dart SDK
分批执行 `dart format <file1> <file2> ...`。每批最多包含 200 个文件，仅格式化
本次实际删除过注释的文件，不格式化无注释文件。这样正常路径只需为每批启动一次
Dart VM，避免逐文件启动进程。

批量格式化退出码为 0 时，整批计为成功。批次失败时，对该批文件逐个再次执行
`dart format <file>`，以获得准确的成功/失败统计。格式化失败时保留已经去除注释
的源码，不执行还原；记录失败路径、退出码和错误输出，然后继续处理其他批次。

## 命令行集成

- 菜单新增 `14.清理 Dart 源码注释`。
- 选择菜单 `14` 时直接处理传入目标项目。
- `x` 临时目录全流程在其他源码生成和改写步骤结束后执行注释清理，确保这些步骤
  新增的注释也能被删除。
- 目标项目缺少 `lib` 目录时抛出清晰错误，不创建目录。

## 结果与映射

控制台输出以下汇总：

- 扫描文件数；
- 修改文件数；
- 删除注释数；
- 格式化成功文件数；
- 格式化失败文件数及路径；
- 失败文件数及路径。

同时更新 `obfuscation_mapping.html`，新增“Dart 源码注释清理”区块，记录：

- `scanned_files`
- `modified_files`
- `removed_comments`
- `formatted_files`
- `format_failed_files`
- `failed_files`

重复执行时更新同一功能区块。第二次执行没有新注释时，源码保持不变，统计中的
修改文件数和删除注释数均为零。

## 错误处理

- 单个文件读取、扫描、校验或写入失败时，记录该文件和原因，并继续处理其他文件。
- 扫描结果无法安全确定注释边界时，不修改该文件。
- 单个文件格式化失败时保留去注释结果，单独记录格式化失败并继续处理。
- 批量格式化失败只对该批次执行逐文件诊断，不影响其他批次。
- mapping 写入沿用现有 HTML mapping 机制。

## 测试

新增 `test/dart_comment_cleaner_test.dart`，覆盖：

- 四种注释形式均被删除；
- 字符串、raw string、三引号字符串中的注释符号保持不变；
- 行尾注释和多行块注释删除后语法有效；
- `foo/* comment */bar` 等边界不会造成 token 粘连；
- 生成文件会被处理，`lib` 外文件不会被处理；
- 无注释文件不被重写；
- 重复执行具有幂等性；
- 单个异常文件不阻断其他文件；
- 仅实际删除过注释的文件会执行格式化；
- 格式化失败时保留去注释结果，并记录失败信息；
- 多个成功文件通过一次批量 format 进程处理；
- 批量 format 失败时逐文件回退并保持准确统计；
- mapping 统计与实际处理结果一致；
- 菜单入口和 `x` 流程包含该功能。
